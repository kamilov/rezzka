# Разработка и отладка

## Локальный запуск

Нужен Node.js 22.12 или новее.

    npm ci
    npm run dev

`npm run dev` запускает интерфейс и локальный адаптер встроенного сервиса на http://127.0.0.1:5173. Управление стрелками, Enter и Escape, мышь тоже работает. Настройки в браузере и на телевизоре проверяются и сохраняются одним и тем же кодом. В пакет для ТВ локальный адаптер не входит.

## Проверки

`npm run check` выполняет по очереди проверку типов, unit-тесты, проверки пакета, сборку и браузерные тесты. По отдельности:

    npm run typecheck
    npm test
    npm run test:release
    npm run test:e2e

Для браузерных тестов установите Chromium командой `npx playwright install chromium` или укажите путь к уже установленному Chromium в `PLAYWRIGHT_CHROMIUM_EXECUTABLE`. `npm run test:e2e` использует отдельное хранилище и не трогает настройки в `.local/data`.

Скриншоты для README пересоздаёт `npm run screenshots`. Сценарий открывает приложение на демонстрационных данных и сохраняет кадры в `docs/screenshots`. Ему нужен доступ в интернет: эпизод Llamigos для кадра в плеере загружается с Wikimedia Commons. Для съёмки поднимается отдельный сервер на порту 5174, поэтому запущенный `npm run dev` не мешает. Источники материалов перечислены в `docs/screenshots/CREDITS.md`.

## Сборка

`npm run package:tv` собирает `.ipk` в каталог `artifacts`. В пакет входят интерфейс и JS-сервис. Идентификатор приложения `ru.kamilov.rezzka`, сервиса `ru.kamilov.rezzka.service`.

## Установка и отладка

Включите на телевизоре Developer Mode и Key Server. Зарегистрируйте устройство командами `npx ares-setup-device` и `npx ares-novacom --device tv --getkey`. Ключи и данные подключения в проект не кладите.

    npm run tv -- install tv artifacts/ru.kamilov.rezzka_0.1.0_all.ipk
    npm run tv -- launch tv
    npm run tv -- inspect tv
    npm run tv -- inspect-service tv

`tv` здесь означает имя зарегистрированного устройства. Сессию Developer Mode нужно продлевать. Если режим отключится, телевизор может удалить установленные для разработки приложения.

На телевизоре сервис хранит настройки, сессию источника и ключ Кинопоиска в `/media/internal/ru.kamilov.rezzka.service`, при локальной разработке в `.local/data`.

## Границы проверок

Проверки в браузере не подтверждают, что на ТВ работают Luna, доступ по локальной сети, хранение данных и медиадвижок. В LG Simulator можно дополнительно проверить веб-интерфейс, но по медиавозможностям он отличается от телевизора. Проект ориентирован на LG OLED55C6RLA с webOS 11.2.0, проверки на этом телевизоре выполняются отдельно.

Доступ по сети включает только пользователь. Временный PIN обменивается на токен сессии. Доступ прекращается, когда режим закрыт, приложение ушло в фон или истёк срок. Настройки сохраняются с номером версии, поэтому устаревшая форма не перезапишет более новые изменения.

## Источник и плеер

Запросы к настроенному зеркалу выполняет встроенный JS-сервис через метод `getSource`, локальный адаптер использует тот же транспорт. Транспорт проверяет HTTPS-сертификаты, ограничивает время и размер ответа и разрешает перенаправления только в пределах origin зеркала.

Cookies аккаунта и имя пользователя хранятся отдельно от настроек, в `source-session.json` с правами 0600. Пароль не записывается. Сессия привязана к origin источника. Вход, выход и чтение состояния аккаунта идут через приватные методы `sourceLogin`, `sourceLogout` и `getSourceSession`. У браузерной панели настроек нет доступа к ним и к `getSource`. Dev-сервер не отдаёт каталог runtime и файлы сессии как статику.

Интерфейс разбирает HTML через `DOMParser` и не выполняет скрипты источника. Разбор каталога, карточек и потоков зависит от разметки и ответов сайта, поэтому их изменения могут потребовать правки парсера. Плеер работает на HTML5 video: MP4 и HLS, если телевизор поддерживает HLS нативно. Субтитры должны быть в формате WebVTT, а сервер должен разрешать их загрузку.

Карточка загружает страницу фильма. В её HTML уже есть серии той озвучки, которую источник отмечает выбранной. Если начинать нужно с другой озвучки, её серии запрашиваются отдельно ещё в карточке. Поток запрашивается после нажатия "Смотреть", уже в плеере.

С какой озвучки и серии начать, решают локальная история Rezzka и отметка аккаунта на карточке источника. Если отметка в аккаунте изменилась с прошлого открытия, то есть фильм смотрели в другом месте, берётся она, иначе локальная история. Когда прошлой отметки нет, выигрывает запись с более поздней серией. Без истории используется озвучка по умолчанию из настроек, затем выбранная на источнике, затем первая доступная. Позицию внутри серии даёт только локальная история и только при включённом возобновлении.

Список "Досмотреть" читается через GET `continue/`. Во время просмотра Rezzka отправляет в аккаунт фильм, озвучку, сезон и серию через POST `ajax/send_save/` с `current_time=1`, как это делают клиенты источника. Точная позиция остаётся на телевизоре. Запрос уходит только при активной сессии и только по HTTPS, без повторов и перенаправлений. Отказ источника просмотр не прерывает.

Первая страница каталога содержит блок обновлений сериалов: вышедшие серии по дням, их озвучку и отметку, следит ли за сериалом аккаунт. По этому блоку сериалы с новой серией поднимаются в начало ряда "Продолжить просмотр" и списка "Досмотреть".

Дополнительные сведения, актёры и авторы, франшиза и расписание серий разбираются из HTML карточки. Расписание включает скрытые на сайте сезоны и строки, отдельные запросы для них не нужны. По расписанию в ряду серий показываются невышедшие серии и серии, которых нет в выбранной озвучке. Скрытые панели и разделы недоступны для навигации пультом.

Комментарии читаются через `ajax/get_comments/` с `news_id`, `cstart`, `type=0`, `comment_id=0` и `skin=hdrezka`. Следующая страница определяется по блоку navigation в ответе, JavaScript источника не выполняется. Текст переводится в безопасную структуру с форматированием и спойлерами, скрипты и встроенные медиа не исполняются. Повтор страницы сохраняет уже загруженное обсуждение, устаревшие ответы не заменяют карточку другого фильма. Комментарии и отметки расписания приложение не записывает.

Карточка занимает одну страницу с общей прокруткой. Стрелка вверх из ряда серий возвращает фокус на выбранный сезон. Полное описание в панели "О фильме" читается стрелками пульта. Фотографии людей обрезаются по кругу.

Страница персоны загружается через `getSource` с `operation: person` одним GET по ссылке источника `/person/ID-name/`, ссылки `.html` тоже поддерживаются. Транспорт проверяет origin и маршрут и запрещает в URL параметры, fragment и credentials. Имя, фотография, факты и группы фильмографии разбираются из HTML без выполнения его скриптов. При переходе в фильм страница персоны сохраняется, возврат восстанавливает фокус на выбранном постере. Поздние ответы не меняют другую страницу.

Сведения Кинопоиска о персоне запрашиваются, только если пользователь задал личный API-ключ kinopoiskapiunofficial.tech. Ключ хранится рядом с настройками сервиса в `kinopoisk-key.json` с правами 0600 и обратно в интерфейс не передаётся. При сохранении ключ проверяется пробным запросом. Сервис обращается только к `https://kinopoiskapiunofficial.tech`, без cookies и перенаправлений, и хранит сведения о персоне в кеше 24 часа. Фотографии принимаются только с хостов Кинопоиска и Яндекса. Для этого есть методы `getKinopoiskStatus`, `setKinopoiskKey` и `getKinopoiskPerson`. Без ключа страница персоны показывает только сведения источника.

Каталог использует маршруты `/{type}/best/{genre?}/{year?}/page/{n}/` и фильтры из HTML источника. Пагинация главной, каталога, поиска и избранного добавляет карточки без повторов, не загружает одну страницу дважды одновременно и игнорирует устаревшие ответы.

Избранное читается через `favorites/` и `favorites/{collectionId}/` с пагинацией. В каких коллекциях лежит фильм, определяется по его карточке на источнике. Изменение отправляет авторизованный HTTPS-запрос `ajax/favorites/` с `action=add_post`, который переключает принадлежность. Перед изменением и после него приложение перечитывает состояние. Повторные нажатия блокируются, перенаправления и автоматический повтор изменяющего запроса запрещены. Если сетевой результат неизвестен, выполняется только проверка состояния. Если не удалась и она, переключатели недоступны до обновления списка.

Создание списка отправляет `name` и `action=add_cat` в `ajax/favorites/`, текущий фильм в список не добавляется. Новый список подтверждается повторным чтением карточки: по идентификатору из ответа или по единственному новому списку с тем же именем. Если результат неизвестен, отправить то же имя ещё раз в текущей сессии приложения нельзя, доступна только проверка списков чтением. Название ограничено 100 символами. Форма и списки управляются пультом, после создания фокус переходит на новый список.

Оценка на постере берётся из оценки Кинопоиска в каталоге. Если её нет, для видимого постера читается краткая карточка через POST `engine/ajax/quick_content.php` с `id` и `is_touch=1`. Из неё берутся оценки Кинопоиска и IMDb. Тот же запрос даёт краткое описание фильма под фокусом на главной. Одновременно идут не больше двух таких запросов, результаты хранятся в памяти до конца сессии. В шапке карточки показываются оценки Кинопоиска и IMDb, в панели "О фильме" все оценки источника, включая HDrezka. Отсутствующие оценки не подменяются нулями.

Карта превью для перемотки читается с того же origin, что и зеркало, пустым POST по адресу из данных плеера. Это WebVTT, где каждая запись указывает картинку-спрайт и область кадра `#xywh=`. Спрайты загружает сама страница. Кнопки плеера имеют доступные названия и подсказки при фокусе.

Браузерные сценарии проверяют каталог, поиск, озвучки, серии, локальное видео, историю и настройки на синтетических ответах. Доступность живого зеркала и воспроизведение с его CDN на ТВ они не подтверждают.

Сценарии авторизации проверяют, что основной интерфейс не показывается до проверки доступа, а также неверные данные, повторный запуск, истечение сессии и выход. Тесты сервиса проверяют сохранение cookies, сброс сессии при смене зеркала из приложения и по сети и защиту от устаревших ответов. Вход с настоящим аккаунтом и работу на ТВ нужно проверять отдельно.
